# 迭代维护规范（落地版）

这份文档把「迭代维护规范」的五条，逐条对到本仓库里**已经存在的机制**上 —— 不是口号，是能跑的命令和能看的位置。

## 1. 功能代码互相隔离、模块独立

**机制：`FEAT` + `MODULE_HOOKS` 两级注册表**

| 位置 | 作用 |
|---|---|
| `index.html` 的 `const FEAT = {...}` | 只存**开关状态**和显示名。加一个功能 = 加一行。 |
| `const MODULE_HOOKS = {...}` | 每个模块自己的 `setup()` / `update(dt,t)` / `teardown()`。 |
| `toggleFeat(k, v)` | **唯一的开关注入口**，只做 `MODULE_HOOKS[k].setup/teardown`，不写任何 `if(k === 'xxx')` 分支。 |
| `updateModules(dt, t)` | 每帧只遍历**开着**的模块，按注册顺序调 `update`。 |

模块之间不互相调用：粒子不碰音频，音频不碰相机，漫游只调 `controls.flyTo`。

**加新功能的标准动作**（三步，不动别人）：
1. `FEAT` 加一行 `xxx: { on:true, label:'...' }`
2. `MODULE_HOOKS` 加一段 `xxx: { setup(){...}, update(dt,t){...}, teardown(){...} }`
3. 需要 UI 的在 `setupModules()` 里加控件

**已经被测试锁住**：`test/verify.js` 有三条断言 —— 每个 `FEAT` 项必须有对应钩子、`toggleFeat` 不许写死分支、`updateModules` 必须按模块分发。谁破坏隔离，`node test/all.js` 立刻红。

## 2. 留存稳定基线版本用于备份

**机制：git tag + 单文件产物**

- 每次验收通过的版本打 tag：`git tag -a v3.1-stable -m "v3.1 稳定基线"`，然后 `git push origin v3.1-stable`。
- 回退到任意基线：`git checkout v3.1-stable`（只读查看）或 `git reset --hard v3.1-stable`（真回退）。
- 单文件产物 `楚门的2.0世界.html` 由 `node build-single.js` 从 `index.html` 生成，可单独存盘备份 —— 这也是发给别人的离线版本。
- 版本变更一律记进 `CHANGELOG.md`。

## 3. 改动前校验和现有功能兼容性

**机制：pre-commit 钩子跑全套**

`.git/hooks/pre-commit` 每次提交自动执行 `node test/all.js`，红就不许提交：

```
verify（静态验收）→ smoke（真跑 init 全流程）→ security（55 条）→ feedback（17 条）→ subpath（子路径部署）
```

改动前先手动跑一次看基线是否本来就是绿的：
```
node test/all.js
```
不绿先修绿再动代码 —— 否则分不清是新改动坏的还是本来就坏。

## 4. Bug 按对应模块单独修复，不全局重写

**机制：钩子分段，定位即修复点**

| 症状 | 改哪一段 |
|---|---|
| 没声音 / 音色不对 | `audioEnsure / audioLoop / audioNote / audioTick` |
| 粒子不出现 / 颜色不对 | `buildParticles / updateParticles / particleWeatherSync / disposeParticles` |
| 天气切了但场景没跟着变 | `lerpWeather` 与 `SKY` 表 |
| 点门没反应 | `onSceneTap / setDoor / setupTap` |
| 视角按钮飞错地方 | `VIEWS` 表 / `applyView` |
| 帧率掉 | `perfTick` 与 `DPR_CAP` |
| 面板布局错位 | `index.html` 里对应 `@media` 块 |
| 意见发不出去 | `sendFeedback` 与 `FB_RELAY`（注意必须带 Referer，见下） |

**不要**为了修一处去重写 `init()` 或 `animate()`。这两个函数只做装配和调用，逻辑都在模块里。

## 5. 保证 GitHub Pages 可以正常部署

**机制：子路径测试 + 部署后实探**

- 本地先验：`node test/subpath-check.js` —— 把页面复制到临时目录的 `/forest-house/` 子路径下起服务器、用无头浏览器真渲染，断言主页与 `js/three.min.js` 都 200、没有请求打到站点根路径、截图非空。**部署前就能知道会不会白屏。**
- 部署后验：`node test/live-check.js` —— 探线上地址的主页、`js/three.min.js`、`.nojekyll`，打印状态码与字节数。
- 硬性约束（踩过坑的）：
  - 资源必须**相对路径**（`js/three.min.js`，不是 `/js/three.min.js`），否则子路径部署必挂。
  - 下划线开头的文件名（`_xxx.html`）在 Pages 上会被 Jekyll 忽略 → 404，别用。
  - 站点是**整仓发布**（branch deploy），推上去的东西都是公开的，别提交密钥、`feedback.jsonl`、`tunnel-url.txt`。

## 顺手记住的三条教训

1. **文本编辑只用编辑工具**，别用 shell 做中文替换 —— 本项目两次把 `index.html` 写成乱码，都是 `Get-Content | Set-Content` 干的。
   另外：**控制台里显示乱码 ≠ 文件坏了**。终端按 ANSI/GBK 解码 UTF-8 时就会花屏，实际文件可能完好。判断依据只有一个 —— 用编辑器/`read` 打开文件看真实字节，别信控制台。
   已实测：`feedback.jsonl` 里中文经 `POST /api/feedback` 落盘完整无损（控制台看到的是假象）。
2. **FormSubmit 必须带 Referer**：页面头部有 `<meta name="referrer" content="no-referrer">`，所以 fetch 上要单独写 `referrer:location.href` + `referrerPolicy:'unsafe-url'`，否则回「not a web server」。
3. **无头截图不决定 CSS 视口**：`--window-size` 只改 PNG 尺寸，布局仍按 496×648 跑。判断布局要看 `getBoundingClientRect`，别拿被裁过的截图当证据。
